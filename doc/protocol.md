# Protocol

SWARM runs the Zcash protocol as implemented by the Zebra full node, with its own network definition. This page says exactly what is inherited and what SWARM defines, so a reader can check each claim against the source.

## Inherited, unmodified

| Area | What SWARM uses | Where to check |
| --- | --- | --- |
| Consensus rules | Zebra's block and transaction validation, including the network-upgrade rule set active on Zcash mainnet at the time of the fork | `zebra-consensus`, `zebra-chain` in [privacy-zebra](https://github.com/Swarmcoin/privacy-zebra) |
| Proof of work | Equihash 200,9 with Zcash's difficulty adjustment (DigiShield v3 variant, 75-second target spacing, averaging window 17 blocks) | `zebra-chain/src/work` |
| Shielded pools | Sapling and Orchard; transparent pay-to-public-key-hash and pay-to-script-hash | upstream crates `sapling-crypto`, `orchard`, `zcash_primitives` |
| Transaction format | Zcash v5 transactions | `zebra-chain/src/transaction` |
| Emission arithmetic | Block subsidy, halving and funding-stream arithmetic of Zebra; SWARM only sets the amounts, heights and recipients | `zebra-chain/src/parameters/network/subsidy.rs` |
| Address encoding | Bech32m unified addresses, Base58Check transparent addresses | `zcash_address` |
| Light-wallet protocol | The `CompactTxStreamer` gRPC service of the light-wallet protocol | [privacy-lightwallet-protocol-rust](https://github.com/Swarmcoin/privacy-lightwallet-protocol-rust) |

No cryptographic primitive, proving system or parameter set is modified. The Sapling and Orchard parameters are the public ones generated by the Zcash ceremonies.

## Supply

With a 6.25 SWM subsidy halving every 1,680,000 blocks, the inherited arithmetic emits **20,999,987.3152 SWM** over 30 eras; the per-era figures are in [economics.md](economics.md). At 75-second blocks the first era lasts about four years.

## What a transaction reveals

| Kind | On the chain | To the light-wallet server |
| --- | --- | --- |
| Shielded to shielded | that a transaction exists, its fee, its size | which encrypted outputs the wallet fetched and trial-decrypted; not the amounts or counterparties |
| Transparent to transparent | everything, as in Bitcoin | the addresses the wallet asked about |
| Mixed | the transparent side in full, the shielded side as above | both of the above |

The wallet defaults to shielded addresses and labels every address with its network and kind.

## Network upgrades

Changes to the chain rules ship as announced network upgrades with an activation height, exactly as upstream does. Node operators and miners update before the height; wallets keep working through the light-wallet server. There is no upgrade scheduled at the time of writing.
